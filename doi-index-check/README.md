# doi-index-check

**この道具は、この場所の中に置いてある。**独立したリポジトリではない。
GitHub App の権限では新しいリポジトリを作れず、作成だけが手作業になるためである。
**切り出すのはいつでもできる。**中身は独立して動く。

DOI を一件与えると、その番号がどの索引に載っているかを一つずつ当たって表にする。

鍵は要らない。API の契約も要らない。**当たるのは、認証なしで開いている口だけである。**

```
node check.js 10.5281/zenodo.22058254
node check.js 10.5281/zenodo.22058254 --mail you@example.com
node check.js https://doi.org/10.5281/zenodo.22058254 --json
```

## この道具が守っている一つのこと

答えは四つに分かれる。

| 状態 | 意味 |
| --- | --- |
| **載っている** | その場が、その番号を持っていると答えた |
| **載っていない** | その場が、その番号を持っていないと答えた |
| **確かめていない** | 当たっていない。鍵が要る場、規約が禁じている場、連絡先が要る場 |
| **落ちた** | 当たったが、答えが読めなかった。通信の失敗、5xx、壊れた応答 |

**「確かめていない」を「載っていない」と読まない。**無いことと、確かめられなかったことは違う。

通信が失敗したときに「載っていない」と書く道具は、無いことの証明を捏造している。
この道具は、応答が明示的に「無い」と言ったときにしか「載っていない」と書かない。
404、あるいは宣言された欄が空であるか、件数がゼロであるか。それ以外は「落ちた」になる。

Unpaywall は `--mail` を渡さなければ「確かめていない」で止まる。当たらない。

Altmetric の 404 は「言及が無い」であって「その番号が存在しない」ではない。
表では「載っていない」と出るが、意味は計測の欄に限られる。

### 鍵が要る（7）—— 当たらない

BASE、CORE、Scopus、Web of Science、Dimensions、Lens.org、PlumX。

いずれも登録か購読か鍵が要る。この道具は口を持たない。**「確かめていない」で止まる。**

### 規約が自動取得を禁じている（3）—— 当たらない

Google Scholar、ResearchGate、Academia.edu。

**規約と robots.txt が自動取得を禁じている。**`targets.json` に url を書いていない。
書いていないことを検査が見ている。人が手で見ること。

## 合法の範囲

**この道具が守っていること。**

1. **認証を送らない。回避もしない。**鍵の要る場には当たらない。当たらないことを
   検査が見ている（`targets.json` に url を書いていない）。
2. **規約が自動取得を禁じている場に当たらない。**Google Scholar、ResearchGate、
   Academia.edu。**url を書いていない。**書けば検査が落ちる。
3. **HTML の頁を掻き取らない。**当たるのは、場の側が API として公開している口だけである。
4. **一件ずつ順に当たる。**並べて叩かない。既定で 1200 ミリ秒空ける。
5. **429 を受けたら `Retry-After` に従う。**待って一度だけ引き直す。二度目は諦める。
6. **名乗る。**User-Agent に道具の名と版とリポジトリの所在を入れる。
   Wikidata はこれを明文で求めている。
7. **一件の DOI を調べる道具である。**目録を丸ごと収穫する作りにしていない。

**Altmetric は非商用に限られる。**大量取得には登録が要る。この道具は一件ずつしか
当たらないが、**商用に使うなら Altmetric の欄を外すこと。**

**根拠は場ごとに `targets.json` の `terms` に書いてある。**当たる先を足すときは、
そこに根拠を書かないと検査が落ちる。

**これは法律意見ではない。**各場の規約は変わる。**使う側が、使う時点の規約を見ること。**

## 行儀

- 一件ずつ順に当たる。並べて叩かない。
- 既定で **1200 ミリ秒**空ける。`--gap` で変えられる。
- User-Agent に道具の名と版とリポジトリの所在を入れる。
- 429 を受けたら `Retry-After` に従って一度だけ待って引き直す。二度目は諦める。
- 20 秒で切る。本文は 2 メガバイトで切る。

数十件の番号を回すときは、間隔を広げるか、日をまたぐ。

## 検査

```
node verification/check_tool.js          # 通す
node verification/check_tool.js --break  # 壊して、落ちることを確かめる
```

検査は **52 項目**。外へは一度も出ない。`fixtures/` の見本だけで回る。
見本で回しているあいだに `https.request` が呼ばれたら落ちる。それも項目の一つである。

通ることでは検査を信用しない。`--break` は、もとを書き換えた写しを作り、
同じ判定をその写しに当てて、**落ちることを確かめる**。壊す先は **33 通り**。
写しは一時ディレクトリに作る。`check.js` と `targets.json` と `README.md` は触らない。

検査が見ているのは、主に次の三つである。

1. 目録の形。識別子が重複していないこと、鍵の要る場と禁じられた場に url が無いこと。
2. 判定の芯。500 と 403 と壊れた JSON が「載っていない」にならないこと。
3. 散文の数。この README の「29」「19」「7」「3」「52」「33」が実際と合うこと。

## 当たれない場所で回したとき

外へ出られない環境で回すと、当たる 19 はすべて「落ちた」になる。
「載っていない」は一つも出ない。それが正しい振る舞いである。

この道具を書いているあいだ、実際に一度だけ「載っていない」が出た。
串が返した 403 を、状態番号だけで決める当て方が素通ししていた。
見本での検査は通っていた。**外に当てて初めて出た誤りである。**
直したうえで、同じ形を捕まえる項目を三つ足した。
