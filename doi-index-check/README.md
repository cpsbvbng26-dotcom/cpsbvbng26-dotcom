# doi-index-check

**この道具は、この場所の中に置いてあります**。独立したリポジトリではありません。
GitHub App の権限では新しいリポジトリを作れず、作成だけが手作業になるためです。
**切り出すのはいつでもできます**。中身は独立して動きます。

DOI を一件与えると、その番号がどの索引に載っているかを一つずつ当たって表にします。

鍵は要りません。API の契約も要りません。当たるのは、認証なしで開いている口だけです。

```
node check.js 10.5281/zenodo.22058254
node check.js 10.5281/zenodo.22058254 --mail you@example.com
node check.js https://doi.org/10.5281/zenodo.22058254 --json
```

## この道具が守っている一つのこと

答えは四つに分かれます。

| 状態 | 意味 |
| --- | --- |
| **載っている** | その場が、その番号を持っていると答えた |
| **載っていない** | その場が、その番号を持っていないと答えた |
| **確かめていない** | 当たっていない。鍵が要る場、規約が禁じている場、連絡先が要る場 |
| **落ちた** | 当たったが、答えが読めなかった。通信の失敗、5xx、壊れた応答 |

**「確かめていない」を「載っていない」と読みません**。無いことと、確かめられなかったことは違います。

通信が失敗したときに「載っていない」と書く道具は、無いことの証明を捏造しています。
この道具は、応答が明示的に「無い」と言ったときにしか「載っていない」と書きません。
404、あるいは宣言された欄が空であるか、件数がゼロであるか。それ以外は「落ちた」になります。

Unpaywall は `--mail` を渡さなければ「確かめていない」で止まる。当たりません。

Altmetric の 404 は「言及が無い」であって「その番号が存在しない」ではありません。
表では「載っていない」と出るが、意味は計測の欄に限られます。

### 鍵が要る（7）—— 当たらない

BASE、CORE、Scopus、Web of Science、Dimensions、Lens.org、PlumX。

いずれも登録か購読か鍵が要ります。この道具は口を持ちません。「確かめていない」で止まる。

### 規約が自動取得を禁じている（3）—— 当たらない

Google Scholar、ResearchGate、Academia.edu。

**規約と robots.txt が自動取得を禁じています**。`targets.json` に url を書いていません。
書いていないことを検査が見ています。人が手で見ること。

## 合法の範囲

この道具が守っていること。

1. 認証を送らない。回避もしない。鍵の要る場には当たらない。当たらないことを
   検査が見ている（`targets.json` に url を書いていない）。
2. **規約が自動取得を禁じている場に当たらない**。Google Scholar、ResearchGate、
   Academia.edu。**url を書いていません**。書けば検査が落ちます。
3. **HTML の頁を掻き取りません**。当たるのは、場の側が API として公開している口だけです。
4. **一件ずつ順に当たります**。並べて叩きません。既定で 1200 ミリ秒空けます。
5. **429 を受けたら `Retry-After` に従います**。待って一度だけ引き直します。二度目は諦めます。
6. **名乗る**。User-Agent に道具の名と版とリポジトリの所在を入れます。
   Wikidata はこれを明文で求めています。
7. **一件の DOI を調べる道具です**。目録を丸ごと収穫する作りにしていません。

**Altmetric は非商用に限られる**。大量取得には登録が要る。この道具は一件ずつしか
当たらないが、商用に使うなら Altmetric の欄を外すこと。

**根拠は場ごとに `targets.json` の `terms` に書いてある**。当たる先を足すときは、
そこに根拠を書かないと検査が落ちます。

**これは法律意見ではありません**。各場の規約は変わります。使う側が、使う時点の規約を見ること。

## 行儀

- 一件ずつ順に当たります。並べて叩きません。
- 既定で **1200 ミリ秒**空けます。`--gap` で変えられます。
- User-Agent に道具の名と版とリポジトリの所在を入れます。
- 429 を受けたら `Retry-After` に従って一度だけ待って引き直します。二度目は諦めます。
- 20 秒で切ります。本文は 2 メガバイトで切ります。

数十件の番号を回すときは、間隔を広げるか、日をまたぐ。

## 検査

```
node verification/check_tool.js          # 通す
node verification/check_tool.js --break  # 壊して、落ちることを確かめる
```

検査は **52 項目**。外へは一度も出ません。`fixtures/` の見本だけで回ります。
見本で回しているあいだに `https.request` が呼ばれたら落ちます。それも項目の一つです。

通ることでは検査を信用しない。`--break` は、もとを書き換えた写しを作り、
同じ判定をその写しに当てて、**落ちることを確かめます**。壊す先は **33 通り**。
写しは一時ディレクトリに作ります。`check.js` と `targets.json` と `README.md` は触りません。

検査が見ているのは、主に次の三つです。

1. 目録の形。識別子が重複していないこと、鍵の要る場と禁じられた場に url が無いこと。
2. 判定の芯。500 と 403 と壊れた JSON が「載っていない」にならないこと。
3. 散文の数。この README の「29」「19」「7」「3」「52」「33」が実際と合うこと。

## 当たれない場所で回したとき

外へ出られない環境で回すと、当たる 19 はすべて「落ちた」になります。
「載っていない」は一つも出ません。それが正しい振る舞いです。

この道具を書いているあいだ、実際に一度だけ「載っていない」が出ました。
串が返した 403 を、状態番号だけで決める当て方が素通ししていました。
見本での検査は通っていました。外に当てて初めて出た誤りです。
直したうえで、同じ形を捕まえる項目を三つ足しました。
