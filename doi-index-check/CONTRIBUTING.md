# 関わり方

**この道具は、無いことと確かめられなかったことを分けるために書いた。**
その区別を崩さない変更だけを受ける。

## 受けるもの

**当たる先を足す**。認証が要らず、規約が自動取得を禁じていない口であること。
`targets.json` に一行足し、**`terms` に根拠を書く**。根拠が無い行は検査が落とす。

**判定の穴を直す**。応答の形が変わって判定がずれた、という報告と直し。

**壊す先を足す**。検査が効いていない箇所を見つけたら、それを壊す一行を添える。

## 受けないもの

**鍵の要る場を足すこと**。この道具は鍵を持たない。持てば別の道具になる。

**規約が自動取得を禁じている場を足すこと**。Google Scholar、ResearchGate、
Academia.edu。**検査が url の有無を見ている。**

**HTML を掻き取る経路**。当たるのは API として公開されている口だけである。

**判定に推論を入れること**。似ているかどうかで決めない。あるか無いか、
数がゼロより大きいか、それだけで決める。

**通信の失敗を「載っていない」と読む変更**。これを入れると、この道具は
無いことを捏造する。**検査が十箇所以上で見ている。**

## 出す前に

```
node verification/check_tool.js
node verification/check_tool.js --break
```

**両方通すこと**。`--break` は、もとを書き換えた写しに同じ判定を当てて、
落ちることを確かめる。**壊しても通った項目があれば、終了コード 1 で止まる。**

**数を書き足したら、その数を検査に足す**。README の「29 の場」「当たるのは 19」
「検査は 52 項目」「壊す先は 33 通り」は、すべて機械で数え直している。

## 支えの範囲とこれからの見込み

**一人で書いている**。返答の速さは約束できない。

**直すもの**。判定の誤り、規約に反する当て先、検査が効いていない箇所。
これらは報告を受けたら直す。

**直さないもの**。上の「受けないもの」に当たる要望。設計の芯なので、
要望の数では変わらない。

**止めるとき**。止めるなら README にそう書く。黙って放置しない。
