## 時間の上限

運営に使う時間は、週に 20 時間までです。
上限を超えた週は、その週のうちに新しい作業を始めません。
保守と修正は、上限を超えた週も続けます。

ここで言う新しい作業は、頁・機能・検査・文書を新しく足すことです。
保守と修正は、壊れたものを直すこと、誤りを正誤表に記すこと、検査の期待値を実物に合わせることです。
週は月曜から日曜までとします。
時間は利用者が数えます。
機械では数えません。

## 新しい案を足す基準

案（利用者が確かめる）。
新しい案は、次の五つを全部満たすときだけ足します。

1. 決めごと 15 の範囲にあること（学部一年次の成果の続きか修正、または JOSS などの経路）
2. 機械で確かめられる形で書けること（数を書くなら、その数を数える検査も足す）
3. 時間の上限の内に収まること（収まらない週は、次の週に回す）
4. 外へ要求を出さない作り（CSP `default-src 'none'`）を崩さないこと
5. 消すときの手順が先に書けること

一つでも欠ければ、足さずに、見送った理由とともに記録します。

## 査読を受けた成果を載せる場所

まだ一件もありません。
載せる場所は先に決めておきます。
査読前の稿と混ざらないようにするためです。

| 載せるところ | 書き方 |
| --- | --- |
| トップの頁 | 「査読を受けた成果」の節を新しく立て、査読前の稿の節より前に置きます |
| 作品の目録 | 種類はそのままにし、状態の欄に「査読済み」を足します |
| CV | 「査読を受けた成果」の節を、修了証の節の前に置きます |
| researchmap と HAL | 論文の枠に入れるのは、載ったものの数え方の決め（2026-09-26）に合うものだけです |

査読前の稿は、査読を受けた版が出ても消しません。
二つの間は、目録の行で互いに指し合うようにします。
