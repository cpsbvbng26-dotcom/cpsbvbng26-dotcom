# 続けられなくなったとき

この頁は、運営を続けられなくなったときの手順と、頼っている外のサービスが止まったときの影響をまとめた記録です。
2026-11-11 に置きました。
研究の系列のサイト全部に共通です。
百本ノック四の 302〜305・308・310 の答えです。

## 順番

止めるときは、凍結・告知・保存の順に進めます。
順番を入れ替えると、告知のあとに中身が動き、告知した状態と配っている状態が食い違います。

| 段 | すること | 誰が |
| --- | --- | --- |
| 1. 凍結 | 各リポジトリの README の札の状態を「凍結」に変え、目録の状態の列も同じにします | 利用者。手が届かなければ、この頁を読んだ人が issue で知らせます |
| 2. 凍結 | GitHub の各リポジトリを Archive にします（Settings → General → Danger Zone → Archive this repository） | 利用者 |
| 3. 告知 | トップの頁の冒頭に、止めた日と理由を一文で書きます | 利用者 |
| 4. 保存 | Zenodo に最後の版を出します | 利用者 |
| 5. 保存 | 配っている頁の写しを Wayback Machine に頼みます（`wayback.yml` を手で起こす） | 利用者 |
| 6. 保存 | Software Heritage に保存を頼みます | 利用者 |

作業環境からは、Release の作成も枝の削除も通りません（403）。
どの段も、利用者の手になります。

## GitHub が使えなくなったとき（写しの場所）

GitHub の外に、履歴ごとの写しを置く案です。
写し先は Codeberg を想定しています。
写しを作るには、利用者のアカウントが要ります。
手順は次のとおりです。

1. Codeberg でアカウントを作り、二段階認証を入れます
2. 「New Migration」から GitHub を選び、リポジトリの URL を一つずつ入れます
3. 「This repository will be a mirror」に印を付けます。Codeberg が定期に取り込みます
4. 研究の系列の 10 と、Sophaxis・deposit-check を同じ手順で写します

写しは読むためのもので、そこで書き換えはしません。
写しを作った日は、この頁の表に足します。

| リポジトリ | 写し先 | 作った日 |
| --- | --- | --- |
| （まだ無い） | | |

## Vercel が使えなくなったとき（配信先の切り替え）

サイトの中身は、リポジトリの根にある静的な頁です。
生成は手元で済ませてから写しているので、配信先では何も組み立てません。
GitHub Pages に切り替える手順は次のとおりです。

1. リポジトリの Settings → Pages で、Source を「Deploy from a branch」、Branch を `main`、フォルダを `/ (root)` にします
2. 公開の URL は `https://cpsbvbng26-dotcom.github.io/cpsbvbng26-dotcom/` になります
3. `sitemap.xml`・`robots.txt`・各頁の `canonical` は、いまの URL のまま残します（下の「URL が変わったとき」）

予想のサイト（`trinity-operator` の `site/`）と Sophaxis も、同じ手順で GitHub Pages に移せます。
どれも無料の範囲で済みます。

## URL が変わったとき

独自のドメインは持ちません。
いまの正の URL は `https://cpsbvbng26-dotcom.vercel.app/` です。

方針は三つです。

1. 正の URL は、変わるまで動かしません。DOI と CITATION.cff と ORCID が指しているからです
2. 変わったときは、古い場所に、新しい場所への一本のリンクだけを置いた頁を残します。転送の設定が使えるなら 301 を使います
3. DOI の側（Zenodo の記録）の URL は、利用者が新しい版を出すときに直します

以前に一度、GitHub Pages を正本にして Vercel から 307 で送り返していた時期があります。
その記録は `deploy/vercel/README.md` にあります。

## オフラインで読める一つのファイル

サイト全体を ZIP にして、Release に添える仕組みを置きました。
`.github/workflows/offline.yml` を手で起こすと、配っている頁と図を一つの ZIP にまとめ、Actions の成果物として残します。
外へ要求を出さない作りなので、ZIP を展開して `index.html` を開けば、そのまま読めます。

## 頼っている外のサービス

| サービス | 何に使っているか | 止まったときの影響 | 代わり |
| --- | --- | --- | --- |
| GitHub | リポジトリ、検査（Actions）、issue、GitHub Pages | 書き換えも検査も止まります。配っている頁は Vercel に残ります | 上の写し（Codeberg） |
| Vercel | サイトの配信（トップ、予想のサイト、Sophaxis） | サイトが読めなくなります。中身は GitHub に残ります | GitHub Pages |
| Zenodo | DOI と、版ごとの保存 | 新しい版の DOI が出せなくなります。出した DOI は DataCite に残ります | Software Heritage に保存を頼んだリポジトリは、そこに中身が残ります |
| DataCite | DOI の登録情報 | DOI の名前解決と登録情報が引けなくなります | DOI の番号は各リポジトリの CITATION.cff と doi-index に残っています |
| ORCID | 著者の識別子 | 著者の名寄せが引けなくなります。番号はどこにでも書いてあります | 無し。番号は残ります |

## アカウントを失わないために

GitHub のアカウントを失うと、全部に手が届かなくなります。
二段階認証と復旧の手段を、年に一度確かめます。
手順は次のとおりです。

1. Settings → Password and authentication で、二段階認証が有効なことを見ます
2. 復旧用のコード（Recovery codes）を表示し、手元の控えと一致することを確かめます
3. 予備の手段（二つ目の鍵か、認証のアプリ）が登録されていることを見ます

確かめた日は、利用者が自分の控えに書きます。
この頁には、手段そのものを書きません（決めごと 9）。
