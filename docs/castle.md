# 城の縄張り

README から移した、十のリポジトリを城の部位に当てた図です。2026-09-18 に作り、2026-11-12 に README からここへ移しました。

十のリポジトリと、その外側の関係を、城の部位に当てて並べます。
喩えであって設計図ではありません。ただし当てはめると、弱点の位置が同じ形で出てきます。

**当てはめたものは三つあります**。城内の十、城の設備、城外です。
城内の各曲輪には、墨付（自分の DOI）と凍結された版と免状を入れてあります。
いずれも各リポジトリの `CITATION.cff` と remote から機械で読んだものです。

この図の墨付と凍結は、2026-09-18 に読んだときのものです。その後、墨付なしとした六つ（天守閣・詰丸・石垣・出丸・二の丸、三の丸の `naval-gazette-notes`）にも、2026-11-07 までにリポジトリ自身の DOI が付きました。番号は [docs/doi-index.md](doi-index.md) の R1〜R12 にあります。下の表と数と弱点の記述は、その日のまま残しています。

**本丸は六つあり、どれも城の外にあります**。人を探しに来た者が着いて、そこで止まる
場所です。運営母体まで下の表に並べてあります。本丸は正本ではありません。

当てはめて出た弱点は二つです。

一つ。**城内の中枢四つが、墨付も凍結も持っていません**。天守閣・詰丸・石垣・出丸です。
引用できる識別子も、固定された版もありません。

二つ。**本丸の三つは、同じ手が計測も持っています**。SSRN と PlumX は Elsevier、
Google Scholar は自分で被引用数を数え、Kudos は共有の経路を数えます。
置いた先が数えているとき、その数は独立した外部の目ではありません。

**どちらも、当てはめる前には見えていませんでした**。喩えが役に立ったのはそこです。

### 本陣は城の中に無い

本陣は作業のセッションです。城外の仮設であり、放置すれば回収されます。
残るのは push したものだけです。会話も、検査の出力も、作業ツリーも残りません。

本陣が落ちても城は落ちません。逆に、本陣で作ったものを城に入れないまま陣を払えば、
それは無かったことになります。

### 縄張りから見える弱点

**墨付を持たない曲輪が六つあります**。十のうち、リポジトリ自身の DOI を持つのは四つ
（`errata-check` / `researcher-profile` / `justice-and-algorithms` / `solitary-school`）で、
残る六つにはありません。天守閣・詰丸・石垣が、その六つに含まれます。

いちばん効くのは石垣です。`self-correction` は全曲輪が訂正の正本として指しているのに、
DOI を持っていません。引用できる識別子の無い石垣です。

詰丸と二の丸と三の丸の一部は、論文のほうに DOI があります。**リポジトリを引くことは
できません**。論文を引くことはできます。

望楼が見ているのは十です。**十で全部です** —— そう確かめたのは、
利用者から「無いはずだ」と指摘されたあとです。それまで、この縄張りには
存在しないリポジトリが一つ載っていました。根拠はこの作業環境に残っていた
クローンだけで、リモートを確かめていませんでした。登録簿の `WS-003` にあります。

天守は実戦向きではありません。これは弱点ではなく設計です。防御は石垣と狭間がやっています。
天守が焼けても城は機能します。Pages が止まっても Markdown は読めます。
