# 予告 —— 結果が出る前に書いたもの

この文書は、結果が出ていないことについて書きます。 ほかの記録はすべて、
起きたあとに書いたものです。ここだけが向きが逆です。

## なぜ置いたか

2026-09-19 に、Grok（xAI）から指摘を受けました。誠実さと免疫が同じ装置になっている、
というものです（[objections.md](objections.md) の反論 5）。

登録簿は 92 件あり、すべて結果が出たあとに書いたものです。結果が出たものを記録する
装置は、結果を吸収できます。 外から手続きを突いても「もう記録済み」で終わります。

結果が出ていないものは吸収できません。 そこで、先に失敗条件を書きます。

## 決めごと

1. 結果が出る前に書きます。 コミットの日付が、それを裏づけます。
2. 失敗条件を、結果が分かれる形で書きます。 「うまくいくとよい」は書きません。
   何が起きたら失敗なのかを、一行で書きます。
3. 期限を書きます。 期限が来たら、結果の欄を埋めます。
4. 失敗したものを消しません。 書き換えません。`失敗` のまま残します。
5. 失敗条件を、あとから緩めません。 緩めた時点で、この文書の意味が消えます。
   緩めたかどうかは git の履歴で分かります。
6. 当たったことを手柄にしません。 当たっても、当たったと書くだけです。

## いま分かっていること

P5 はいちばん落ちやすい予告です。 2026-09-19 の時点で、10 リポジトリの star は
すべて 1 件（著者自身）で、fork は 0 件、issue は 2 件とも著者自身のものです。
外部からの接触は、測ると 0 です。

P1 は当てのある相手が残っていません。 依頼は計 3 通・相手 2 人で、一人が断り、
一人は返事がありません。面識の無い相手を探す段階に戻っています。

P1 の先にあった arXiv への投稿は、2026-09-24 に取り消しました。推薦を求めることもやめています。
**失敗条件は動かしません**。取り消したことを理由に、この行を外すことも書き換えることもしません。
期限の 2026-12-31 に推薦が下りていなければ、結果の欄に `失敗` と書きます。

P4 は門 2 がいちばん薄いところです。 JOSS は「著者自身の利用が最低線」と書いて
いますが、同時に「一回の分析のための道具ではなく研究共同体への意味ある寄与」も
求めています。

## この文書の崩し方

- 予告のいずれかが失敗し、その項目が `失敗` として残れば、この装置は自分の予告でも
  負けたことになります。 それが反論 5 への答えになります。
- 逆に、失敗したときに結果の欄が書き換わるか、失敗条件が緩められれば、
  免疫のほうが勝ったことになります。 そのときは反論 5 が正しかったと決まります。
- どちらに転んでも、判定は外から見えます。 この表は git に入っています。
