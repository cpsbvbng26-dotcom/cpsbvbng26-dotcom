# 正本の優先順位

同じ内容が複数の場所にあるとき、**どれを正とするか**を固定します。
新しい順位を作るのではなく、**すでにそう運用しているもの**を書き留めるだけです。

---

## 種類ごとの正本

| 対象 | 正本 | 理由 |
|---|---|---|
| **論文の PDF と書誌** | **Zenodo** | DOI が付き、版が固定される。GitHub 上の PDF は同じものの控え |
| **実装と版管理** | **GitHub** | 履歴・差分・CI がある。Zenodo のアーカイブは特定時点の写し |
| **著者の識別子** | **ORCID** `0009-0000-1406-0547` | 同姓同名と区別できる唯一の識別子 |
| **公開の入口** | **GitHub Pages** `https://cpsbvbng26-dotcom.github.io/cpsbvbng26-dotcom/` | 核の主張・撤回・全成果への導線が一枚にある |
| **撤回と正誤** | **`trinity-infinity/ERRATA.md`** | 何が撤回されたかは、ここだけが正 |

## 同じ人物について、別の媒体に別の記述があるとき

**大谷恒について、GitHub の外にも記述があると外部の点検が述べている**（Google Sites の家系図。
`docs/external-evaluations.md` の九件目）。**その媒体は作業環境から開けないので、内容は確かめていない。**

| 対象 | 正 | 理由 |
| --- | --- | --- |
| **1943年9月11日時点の階級・受章・假記番号** | **史料ノート**（`10.5281/zenodo.22055709`） | 原資料（JACAR `C12070491000`）に当たって書いてある |
| **最終階級・乗艦・配置** | **どこも正ではない** | 公報だけでは確定できないと、そのノート自身が書いている |
| 続柄 | 先祖の公的記録の頁 | 根拠を文書・証言・未確認に分けてある |

**階級が二つ出てくることは、それ自体では矛盾ではない。**公報が記録しているのは、その日の階級である。
のちの昇進を否定しない。**問題は事実ではなく確度である** —— こちらが「確定できない」と書いていることを、
別の媒体で確定して書けば、**同じ著者が二つの基準を使っていることになる。**

**揃え方は一つしかない。**別の媒体の断定に、それを支える別の出典を付けるか、断定をやめるかである。
**こちらの記述を、確度の低いほうへ合わせることはしない。**

## Zenodo との連携についての但書

**Zenodo を正としていますが、この連携は自動ではありません。**
上の表を「仕組みで保証されている」と読まれると誤ります。実際にどこまで保証されて
いるかを、ここに書き出します。

### 1. この作業環境から Zenodo へは、何も送れません

Zenodo には、GitHub の Release を拾って版を固定し DOI を付ける連携があります。
**この作業環境からは、その入口に触れられません。**タグの push が 403 で通らないため、
Release を作れないからです。

Zenodo への登録も、新しい版の作成も、**すべて著者が手で行っています。**
この環境がしているのは、受け取った番号を書き写すことだけです。

### 2. 番号は転記であって、確認ではありません

`zenodo.org` にも `doi.org` にも DataCite にも、この環境からは届きません。
外向きに出られるのは GitHub だけです。

**番号が実在しないと言っているのではありません。**登録したのは著者本人です。
番号は Zenodo が発行したものを、著者が読み取って渡しています。
**存在は著者の証言で立っています。**登録簿が根拠を「紙面」と「証言」に分けて
どちらも数えているのと、同じ扱いです。

確かめられないのは、その先です。

| 疑っていないこと | 確かめられないこと |
|---|---|
| 番号が Zenodo で発行されたこと | ここに書き写した文字列が、その番号と一字一句同じか |
| 著者がそれを読み取ったこと | その番号が、指すつもりのレコードを指しているか |

**起きる誤りは、存在ではなく書き写しのほうです。**
`10.5281/zenodo.22335691` と `...692` の食い違いがその例で、六箇所が `692`、
一箇所だけが `691` です。書き写しの誤りか、概念 DOI と版 DOI の違いかは、
レコードを開かなければ決まりません（次の節）。決まらないものは「未確認」と
書いてあります（[doi-index.md](doi-index.md)）。

### 3. 版の DOI か、概念 DOI かも、判別できません

Zenodo は、全版を代表する DOI（concept DOI）と、その版だけを指す DOI（version DOI）
を別に発行します。**一覧にある番号がどちらなのかは、この環境からは分かりません。**
Zenodo のレコードを開かなければ判別できないからです。

「最新版を指したい」場合に使うべき番号は、この一覧からは選べません。
`10.5281/zenodo.22335691` を未確認のまま置いてあるのは、まさにこの区別が
付かないためです。

### 4. 食い違ったときは Zenodo が正です

書誌、ライセンス表示、版の日付。GitHub 側の記載と Zenodo 側の設定が食い違った
場合は、**Zenodo を正としてください。**GitHub 上の PDF は控えです。

これは `trinity-infinity/README.md` にある注記と同じ扱いです。

### 5. 新しい版を作っても、ここの PDF は変わりません

Zenodo で新しい版を作ることと、このリポジトリの PDF を差し替えることは、
別の操作です。**公開済みの PDF は改変も再生成もしません。**
誤りが見つかったときに直すのは、PDF ではなく `ERRATA.md` のほうです。

逆も同じで、ここで正誤表を直しても Zenodo 側のレコードは変わりません。

### 6. Release が無いことは、何も意味しません

タグの push が 403 で通らないため、**この環境から Release を作った実績はありません。**
GitHub に Release が並んでいないことから、Zenodo の登録状況を推測しないでください。

### 7. この環境がしないこと

| | |
|---|---|
| **番号を推測して埋めない** | 受け取った番号だけを書きます |
| **Release を勝手に作らない** | Zenodo での公開と版の作成は著者の操作です |
| **タグを push しない** | 通らないだけでなく、勝手に版を切らないためでもあります |

## 外部からの評価が付く先

外部の公開レビューの場が受け付けたのは **SSRN の DOI** だけでした。Zenodo の DOI は
対象外です。つまり「引用は Zenodo で」と固定している一方で、**第三者の評価は
SSRN 側にしか残りません。**片方だけを見た読者は、もう片方に気づきません。

SSRN 版があるのは二篇だけなので、**Trinity-Infinity の三本・Fragmentarian・
史料ノートは、この経路では評価を受けられません。**

記録は [external-evaluations.md](external-evaluations.md) にあります。
