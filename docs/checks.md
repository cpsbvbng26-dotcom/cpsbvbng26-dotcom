# 横断の検査の数と、マージの前に見るもの

## 横断の検査の数

`verification/check_ecosystem.js` は、いま 10 リポジトリ横断 944 項目です。

この数を書くのは、この頁だけです。
README、CI の仕事の名前、作業の手順書、現状の自己評価は、この頁を指します。
2026-11-12 まで、同じ数をいくつもの場所に書いて突き合わせていました。
検査を足すたびにその全部を直すことになり、直し忘れが起きやすかったので、一か所に減らしました。
`check_ecosystem.js` が、自分の数とこの頁の数を突き合わせます。
ほかの場所に数を書き戻すと、それも落とします。

## 散文の数の区分

2026-11-18 に、13 のリポジトリの散文に書いた「NN 件・NN 項目・NN 通り」と英語の同じ数を、一つずつ壊しました。
壊すたびに、どの検査が落ちるかを見ました。
落ちなかった数のうち、いまの数には、数え直す宣言を `verification/ecosystem.json` に足しました。
日付の付いた過去の数は、git のその時点のファイルを読むか、その時点の検査を走らせて数え直します。
どちらもできない数は、理由と一緒に `verification/prose-numbers.json` の「数えられない」に置きました。
外のサービスの応答、他人の論文の数、証言、その日の実行の記録がそれに当たります。
行の番号、算術の恒等式、年、注釈、直す前の文の引用は「外す」に置きました。
`check_ecosystem.js` の 13e が、散文の数がどれも区分にあることを見ます。
新しく数を書けば、区分が無くて落ちます。
2026-11-18 に Claude が決めました。数を書き足すたびに、決めごと 5 を機械が思い出させる形にするためです。

新しいリポジトリに様式だけを写せば、落ちます。

## マージの前に見るもの

マージのコミットに開示の二行（`Co-Authored-By` と `Claude-Session`）が付いていないものが、10 リポジトリ合わせて 63 件あります。
数えているのはマージのあとです。`check_ecosystem.js` が、開示の無いマージを数えて 63 と突き合わせます。

2026-11-12 から、PR の段階でも確かめます（`.github/workflows/pr-disclosure.yml`）。
枝のコミットに Claude の `Co-Authored-By` があれば、PR の本文にも開示の行が要ります。
無ければ、その PR の検査が落ちます。

マージのコミットの本文は、PR の段階では確かめられません。
本文は、マージする側がマージの時に API へ渡すもので、それまでどこにもありません。
そこで PR の検査は、マージに渡す本文の末尾に置く二行を、枝のコミットから組み立てて Actions の要約に出します。
マージのあとの件数の検査は、そのまま残します。
PR の段階で止められるのは本文の開示までで、マージのコミットの付け忘れは、あとで数えるほうでしか止まりません。

## issue に答える仕事

本文の空の issue に答える仕事（`empty-issue.yml`）は、15 のリポジトリに一字一句同じ写しを置いています。
正本は、このリポジトリの `.github/workflows/empty-issue.yml` です。
2026-11-18 に利用者が、Sophaxis の #252 が本文の空のまま開かれたことを挙げ、余計な issue を除く仕組みを求めました。
issue の様式は、一部のスマートフォンのアプリやブラウザで表示されないことがあります。
そのとき issue は、題だけを持ち、本文の空のまま開かれます。
この仕事が答えるのは、本文が空か空白だけで、ラベルもコメントも無い、開いている issue です。
PR と、bot が開いたものと、リポジトリの持ち主・メンバー・共同作業者が開いたものには答えません。
issue が開かれたときは、10 分待ってから issue を読み直し、まだ当てはまるときだけ答えます。
週に一度、開かれてから 24 時間を過ぎた issue も見ます。
答えは、ラベル `empty body` と、様式を指す日本語と英語の決まった文のコメント一つです。
あとで本文が書かれれば、ラベルを外します。

この仕事は、issue を閉じず、鍵も掛けず、消しません。
決めたのは Claude で、2026-11-19 です（日本時間）。
題に、削除・権利・個人の情報・氏名・同意の撤回の求めが書かれていることがあります。
語の並びではそれを見分けきれないことは、2026-11-15 の十八度目の点検で分かっています。
Sophaxis のモデレーションの規程も、自動の手順は issue に鍵を掛けないと書いています。
GitHub の説明書（Deleting an issue）は、個人のアカウントが持つリポジトリでは、そのアカウントだけが issue を消せると書いています。
実行の鍵（`GITHUB_TOKEN`）はそのアカウントではないので、この仕事には消せません。
道具は、issue の題も本文も、ログ・環境・コマンドのどこにも書きません。
`check_ecosystem.js` が、写しが同じことと、作った issue の見本での振る舞いを確かめます。
