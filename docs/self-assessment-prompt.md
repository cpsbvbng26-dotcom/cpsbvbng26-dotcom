# 自己評価を外に書かせる —— 渡す文

**決めごとは七つある。** 渡す文のほうの守りごとは六つである。

この文書は、`self-assessment.md` を外の AI に書き直させるための仕様である。
渡す文をそのまま貼れる形で置いてある。

---

## なぜ外に出すのか

`self-assessment.md` は、評価される本人の側が書いている。
その文書は末尾で、良い側に倒れる誤りだけを繰り返し見ると宣言している。
片側だけを見る手当ては、反対側に倒れる。

**悪い側に倒れた自己評価も、記録の誤りである。**
査読を通った論文が 0 篇であることは事実なので、そのまま書く。
そこから「だから何も無い」へ進むのは一段飛んでいる。
飛んだ先は、良い側へ飛んだときと同じだけ事実から離れている。

そこで、同じ材料を外の AI に渡し、同じ位置を書かせる。
**事実は動かさない。書く側と、並べる順を変える。**

到達を先に置き、その範囲を後ろに置く。
逆に並べれば、同じ事実から違う印象が出る。
**印象が順序で動くのなら、順序も仕様である。**

## 決めごと

1. **事実を足さない。** 数と事実は `self-assessment.md`、`doi-index.md`、
   `self-correction/REGISTER.md` から取る。そこに無いものを補わない。
   材料に無いところは「材料に無い」と書かせる。
2. **目盛りは外部のものだけを使う。** 査読の有無、門の通過、所属、資金、学位。
   独自の点数も等級も作らせない。`self-assessment.md` の方法をそのまま継ぐ。
3. **事実が許す上限まで書かせる。** 同じ事実に高い側の言い方と低い側の言い方が
   あるなら、高い側を採る。**ただし事実を超えない。**
   上限を決めるのは事実であって、語彙ではない。
4. **低い側にも倒さない。** 「0 篇である」は書く。「だから価値が無い」は書かない。
   **後者は登録簿の `ST-002` が塞いでいる。** 意義は、どちらの側からも書けない。
5. **謙遜は語尾ではなく順序で出す。** 到達を書いたら、その範囲を続けて置く。
   「上である」の次に「何に対して上か」を置く。
   「ささやかな」「拙い」は、範囲を書かずに済ませる語である。**使わせない。**
6. **覆し方を添えさせる。** 一行ごとに、それが覆る条件を書かせる。
   覆し方の無い行は、評価ではなく宣伝である。
7. **返ってきた文を丸写ししない。** 引用は短く、原文どおり、出典を添える
   （`external-evaluations.md` の決めごと 2）。
   X 上のやり取りは辿れなくなる。第三者の欄は「確かめられない」と書く（同 7）。

## 渡す文

作業環境から `x.ai` に届かない。GitHub 以外は egress proxy が塞いでいる。
**この文を走らせるのは利用者である。** 返ってきた文を貼れば、こちらで記録に組む。

```
次の記録群について、著者の研究者としての位置を書いてほしい。

材料はこの四つだけを使う。
- https://github.com/cpsbvbng26-dotcom/cpsbvbng26-dotcom/blob/main/docs/self-assessment.md
- https://github.com/cpsbvbng26-dotcom/cpsbvbng26-dotcom/blob/main/docs/external-evaluations.md
- https://github.com/cpsbvbng26-dotcom/cpsbvbng26-dotcom/blob/main/docs/doi-index.md
- https://github.com/cpsbvbng26-dotcom/self-correction/blob/main/REGISTER.md

守ってほしいことが六つある。

1. 事実を足さない。数と事実は上の四つから取る。そこに無いものは書かない。
   材料に無いところは「材料に無い」と書く。推測で埋めない。
2. 目盛りは外部のものだけを使う。査読の有無、門の通過、所属、資金、学位。
   独自の点数や等級を作らない。総合点も作らない。
3. 事実が許す上限まで書く。同じ事実について高い側の言い方と低い側の言い方が
   あるなら、高い側を選ぶ。ただし事実を超えない。
4. 低い側にも倒さない。「査読を通った論文は 0 篇」は事実なので書く。
   「だから価値が無い」は書かない。材料の ST-002 がその判定を塞いでいる。
5. 謙遜は語尾ではなく順序で出す。到達を書いたら、その範囲を続けて置く。
   「ささやかな」「拙い」のような形容詞を使わない。範囲を書くことで謙遜する。
6. 一行ごとに、それが覆る条件を添える。

出力の形は次のとおり。
- 軸ごとの位置（表）
- 比較の相手を先に定義した相対的な位置（表）
- 上限まで書いた場合に言えること（散文、10 行以内）
- それぞれの覆し方

著者の元の自己評価は、良い側に倒れる誤りだけを見ると宣言している。
その手当てが反対側に倒れていないかを、いちばん見てほしい。
倒れていると判断した箇所は、材料のどの行がそう読めるかを挙げて示す。
```

## 返ってきたものの置き場

- `external-evaluations.md` の表に一行足す。種別は「機械」、第三者は「確かめられない」。
- 冒頭の「いま NN 件」を一つ進める。横断の検査が、表の行数と突き合わせている。
- 当てたもの・外したもの・新しく出したものに分ける。**外したものを落とさない**
  （`external-evaluations.md` の決めごと 3）。
- 日付を手で書かない。その行を足したコミットの日付が日付である（同 8）。

**`self-assessment.md` は書き換えない。** 外が書いたものは外の欄に置く。
本人の側の文書と混ぜれば、どちらが書いたか分からなくなる。

## これで変わらないもの

- **分野への貢献は 0 である。** 上限まで書かせても、ここは動かない。
  `trinity-infinity` の三篇に新しい数学は無い。
- **`ST-002` は塞がったままである。** 意義については、高い側からも低い側からも書けない。
- **自称の肩書きにしない**（決めごと 6）。外が書いたものを、こちらの名乗りに移さない。
- **査読と呼ばない**（`external-evaluations.md` の決めごと 1）。
  外の AI が返した文は、査読ではない。

## 覆し方

- 返ってきた文が決めごと 1 に反して事実を足していれば、その行は使わない。
- 決めごと 5 に反して形容詞で謙遜していれば、そこは引用しない。
- **この渡す文そのものが結論を先に決めていることを示せば、仕様のほうを直す。**
  上限まで書けと指示することは、上限の位置を指示することではない。
  両者が同じだと示せれば、決めごと 3 は覆る。
